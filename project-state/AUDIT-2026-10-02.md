# Repository Audit: 2026-10-02

Repository: uprealband/perjalanan-band-indie

## Scope
- project memory
- state persistence
- anti-regression structure
- narrative consistency
- machine-readable historical reconstruction

## Findings

### Strong existing foundation
The repository already has:
- archive/ with historical media organized by year/category
- archive-index.json as a machine-readable archive index
- track/ as narrative source
- catalog.json generated from media/story sources
- GitHub Actions for catalog/book generation
- chapter navigation and web/book output
- soundtrack/media linkage

### Missing project-memory layer
No dedicated files were found for:
- current project state
- decisions
- experiments
- hypotheses
- scenarios
- persistent error/anti-regression history

This is the main gap related to repeated AI mistakes.

### Track 01 metadata duplication
Track 01 contains repeated Tokoh, Tempat, and Tahun sections. This is a data-normalization problem, not necessarily a storytelling problem.

### Track 02 metadata inconsistency
Track 02 uses a different heading structure from Track 01 and lacks the same metadata/front-matter pattern. This increases extraction ambiguity.

### Draft/publication ambiguity
The repository contains Track 01 through Track 31 source files, while the current publishing effort is only at Track 01 and Track 02. The dataset therefore needs an explicit distinction between source/draft, reviewed, published, and indexed.

### Causal structure is implicit
The stories contain useful causal chains, for example:
EP completed -> Ismanu leaves -> bassist vacancy -> Eka joins

and:
bassist vacancy -> discussion -> Gerry considered -> Gerry changes instrument -> Apoy recruited

These relationships currently live inside prose rather than explicit machine-readable relation objects.

## Recommended architecture
Keep the current narrative/archive system.

Add:
project-state/CURRENT-STATE.md
project-state/DECISIONS.md
project-state/EXPERIMENTS.md
project-state/SCENARIOS.md
project-state/ERRORS.md

Then introduce structured historical relations incrementally.

## Audit principle
Do not optimize for theoretical elegance first. Make one structural change, publish/test it, measure AI behavior, then iterate.
